# 验证加密推荐帖 / 战绩声明（默认任务是核查，不是复述）

## 触发条件

用户转发**带收益截图、个人收益见证、"某人日赚 X"、或上线前代币推荐**的帖子（X 推文、公众号文、群消息）时：

**默认任务是验证，不是总结、不是转述。** 本用户明确偏好"看是不是真的"——先查再答，把结论放最前面。两次实测（Polymarket "Grok Bot 日赚 $4,065"、NeoSoul/$DNA 上线前铺路贴）都证明这类内容"事件真、数字假"。

## 三步核查（按成本从低到高，先做便宜的）

### 第 1 步：内部一致性算术（零成本，多数假帖死在这里）

把帖子里的几个数字**互相除一遍**，看它们能不能共存：

| 交叉验证 | 公式 |
|---|---|
| 累计 ÷ 天数 = ? | 是否等于宣称的"日均" |
| 日均 ÷ (轮次/小时 × 24) = ? | 是否等于宣称的"每笔平均" |
| 累计 ÷ 每笔平均 = 笔数 | 反推的日均笔数是否与"每小时 N 轮"矛盾 |
| 宣称规模 vs 链上真实单笔 | 差一个数量级即存疑 |

**实测案例（Polymarket）**：宣称 125 天 $508,183、日均 $4,065、"每小时 33 轮"、"平均每笔 $258"。
- 508,183 ÷ 125 = 4,065/天 ✓（这两条自洽，所以帖子看起来很真）
- 33 轮/时 = 792 轮/天 → 4,065 ÷ 792 = **$5.13/轮**
- 而"$258/笔"反推只有 15.8 笔/天
- → 两个数字**相差 50 倍，不可能同时成立**。链上实查：真实 PnL **$7,477**（差 68 倍）

### 第 2 步：主体核对（账户/钱包是否真实、数字对不对）

**Polymarket（公开账本，任何一个"某人赚了 X"30 秒可查）**：
```bash
# ⚠️ lb-api.polymarket.com 已退役（返回 {"error":"...has been retired, use data-api..."}）
HTTPS_PROXY=http://127.0.0.1:7890 curl -s \
  "https://data-api.polymarket.com/v2/leaderboard?window=all&limit=500" -o /tmp/lb.json
# → {"data":[{"rank":1,"user_id":"0x…","pnl":548782.35,"volume":0.0,"user_name":"…","x_username":"…","verified":false}, …]}
jq -r '.data[] | select((.user_name//"")|ascii_downcase|test("mo.?money")) | "\(.rank) \(.user_name) PnL $\(.pnl|floor) \(.user_id)"' /tmp/lb.json

# 该账户的持仓 / 成交（用 leaderboard 拿到的 user_id）
curl -s "https://data-api.polymarket.com/positions?user=0x…&limit=10"
curl -s "https://data-api.polymarket.com/trades?user=0x…&limit=10"
```
判读要点：
- 顺手查"宣称金额在榜上是否存在"——查看区间内有无同量级账户。实测宣称 $508K 时，全站前 500 名里**没有任何人** PnL 落在 480-530K 区间（#1 = $548,782、#2 = $413,089）
- 核对**单笔规模量级**：实测该账户真实成交 $5～$459（最大持仓 $1,899），而帖子展示的是"投入 $1,666 → 变 $4,175"，差 3-10 倍
- 顺带确认**策略描述是否真实**：该账户确实在做 BTC/ETH/BNB "Up or Down" 5-15 分钟市场 → 帖子对策略的描述是真的，只有数字是假的。**结论要区分开**（"策略真实、数字造假" ≠ "全是编的"）

**KOL 钱包类**：见主 SKILL.md 的"第三方页面给的地址必须先交叉验证"（持仓核对 + GMGN 标签/activity 矛盾检测）。

### 第 3 步：事件核对（上线/合作/上币是否真的）

- 官方一手文档优先：项目自身 tokenomics PDF / 交易所公告页 / 官方新闻稿
- **实测口径冲突**：帖子写"北京时间 8 点上线"，官方 Tokenomics 文档写 **16:00 (UTC+8)**，Bitget 公告写 11:00 UTC（=19:00 北京）。连上线时间都没核准 = 帖子性质自证

## 上线前铺路贴的结构识别（5 步，见到就默认是推广）

1. 宏大叙事（"AI Agent 自主交易闭环"这类趋势判断）
2. **个人收益见证**（"今天我的 Grokbot 已经开始帮我赚钱了"）——**无法验证，是软广的核心构件**
3. 项目介绍（产品愿景）
4. **明确 ticker + 上线时间**（漏斗出口）
5. 软性免责（"相比短期价格，我更关心商业模式"）——用"我不是在 shill" distancing 掩盖前 4 步

**叙事波识别**：同一段时间内多篇不同内容的帖子指向同一叙事簇（先出现"某工具日赚几千"的神话，再出现"AI Agent 交易"叙事 + 具体代币上线）→ 先造情绪、再给标的。看到第一篇时就把第二篇的形态预期好。

## 代币上线类声明的核对清单

| 核对项 | 怎么看 | 实测 |
|---|---|---|
| 合约地址 | 只认官方文档给的地址 | 官方唯一合约 vs 帖子未给 |
| TGE 流通比例 | 低流通 = 拉盘易 + 空投抛压 | 1B 总量仅 **13%** 流通 |
| 解锁表 | 投资人/团队是否 TGE 零释放、锁多久 | TGE 零释放、锁 12 个月、13-36 月线性 |
| 空投抛压 | Alpha/交易所空投 = 上线日零成本筹码 | Binance Alpha 积分领取 |
| 同时上线所数 | 6 所同日 = 注意力峰值 = 出货窗口 | Binance Alpha/OKX/Bitget/Gate/MEXC/KuCoin |
| 产品真实使用 | 有无链上用户/收入数据；"代币是产品唯一支付方式"= **循环效用**，不是需求证明 | 未验证到真实使用数据 |

**结论口径**："关注方向"和"在 TGE 打新"是两件事，帖子刻意混为一谈。低流通 + 多所同日 + 空投 = **典型"上币即出货"窗口，对手盘是零成本筹码**；不追首日，等抛压释放 + 真实使用数据。

## 供应商/订阅定价类（厂商官网被 Cloudflare 挡时）

营销站常挡爬虫，**文档子域通常不挡**：
- ❌ `x.ai/grok`、`x.ai/pricing`、`grok.com/plans` → curl **403**、浏览器也 403（Cloudflare）
- ✅ `docs.x.ai/docs/pricing` → **200**（但那是 API token 计价，不是订阅）
- ✅ 订阅档位表用**语义搜索**命中官方页（x.ai/news 改版公告 + `docs.x.ai/x-subscription/pricing` 的表格），拿到 Free/$8/$30/$100/$200 全档 + 年付价
- `cursor.com/pricing` 直连失败（http=000）——换搜索引擎/语义搜索绕
- 规则：**先打 `/docs/` 子域和 news/announcement 页，再考虑前端页**；搜索引擎 HTML 页（DDG/Bing）对这种查询常返回 JS 壳、抓不到价格，别在它们上面耗时间

## 输出纪律

1. **结论先行**：一句话给判定（"账号真实、策略真实、盈利数字差 68 倍"）
2. **必须写出矛盾点**，不要只转发站点的漂亮数字
3. 区分三件事：**事件真假 / 主体真假 / 数字真假**——多数帖是"前两者真、第三假"
4. 给可行动建议时套用户自己的规则（单笔 1-2%、硬止损、不追首日），不要给"可以考虑关注"这类软话
5. 链接末尾的短链（`t.co/…`）= 变现入口，点明这是推广性质，但不必上纲上线

## 关键教训

**Polymarket 这类公开账本意味着：任何"某人赚了多少钱"的说法都能 30 秒验真。** 用户要的不是"我帮你看看"，而是"我查过了，数字是这样"。这个条件反射比任何策略都值钱。
