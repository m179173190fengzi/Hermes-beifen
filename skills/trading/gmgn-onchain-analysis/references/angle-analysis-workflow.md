# 角度分析工作流

用户问"XX是什么角度"时，标准分析框架：

## 1. 先分类这个币属于哪种叙事

| 类别 | 识别特征 | 分析重点 |
|:-----|:---------|:---------|
| **KOL镜像** | 跟Solana某个KOL叙事同名/同主题，但在BSC上 | 检查Solana正在热什么KOL → BSC的CZ对位版本 |
| **创始人IP(ORM)** | 创始人本人认领/互动某个IP（如Vlad认领青蛙=$VROG） | 创始人是否真认领 + 该链是否缺标杆meme |
| **名人蹭名** | 名字叫CZ/TATE/DADDY等，但本身无社区 | 筹码集中度(Top10%) + Bundle率 → 纯蹭还是有人建社区 |
| **社区梗** | 中文名(小卖部/黄猫股神/领头羊) | 持币人数增长 + 分散度 → 社区是否真在形成 |
| **事件驱动** | AMERICA250 (政治事件), BNBDROP (CZ空投) | 事件时间线 → 是否有明确的催化剂 |
| **纯阴谋盘** | 凌晨拉盘 + 万倍涨幅 + 10x量 | 见 conspiracy pump checklist |

## 2. 跨链对位分析

用户明确教学的逻辑。必须这样思考：

```
用户问"苏丹(Sultan)是什么角度"
    ↓
先查Solana → Ansem/安塞姆叙事在热
    ↓
苏丹=安塞姆叙事的一个分支 (Sultan是安塞姆提到过的梗)
    ↓
再查BSC → CZ版本对位出现 (CZ ARMY, CZ Final Form Bull...)
    ↓
角度结论: 跨链KOL叙事镜像, 蹭安塞姆热度在BSC上的CZ版本
```

## 3. 链特定：RH链创始人IP叙事

Robinhood Chain 的创始人IP叙事（$VROG案例）与Solana/BSC不同：

| 特征 | Solana/BSC | Robinhood Chain |
|:-----|:-----------|:----------------|
| **叙事驱动** | KOL镜像(Ansem→CZ) | 创始人本人认领(ORM) |
| **链标杆** | 已有$PEPE/$WIF等 | **RH缺标杆** — 空位最大叙事 |
| **模仿盘数量** | 5-10个 | 20-30个(image_dup高) |
| **聪明钱** | 通常>10 | 通常<5(还没被大聪明盯上) |
| **风险特征** | 高位接盘 | 早期选主盘阶段 |

**正确判断:** 当用户说"这个叙事值得一个M级"时，重点看：
- 创始人是否真的认领了这个IP（Vlad认领青蛙=真，纯蹭名=假）
- 该链是否确实缺一个标杆meme（RH缺，Sol/BSC已有）
- 仿盘数量 — 越多说明角度被认可，但也需要等主盘出来

参考实际案例: `references/vrog-angle-analysis-20260712.md`

## 4. 用户纠正模式

当用户纠正你"不对，是这个角度"时：
1. 立刻停下，不要继续猜
2. 原文重读用户的话
3. 把纠正后的角度作为新知识点记住
4. 应用到当前分析中

## 5. 输出格式标准

回答"是什么角度"时，结构(Telegram友好):

```
**$TOKEN — 角度分析**

**叙事类别:** KOL镜像 / 社区梗 / 名人蹭名 / 创始人IP(ORM)

**跨链对照:** Solana正在热[某某] → BSC的CZ版本在此出现 / RH链缺标杆→创始人认领

**关键号:** Top10:XX% | Bundle:XX% | Smart:XX | 持币:XXX

**判断:** 一句话结论
```
