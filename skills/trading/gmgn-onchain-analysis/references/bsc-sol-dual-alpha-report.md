## 2. 硬规则（优先级高于 skill 文档）

## 3. ⚠️ 75 分制的算术约束（重要校准）

`A(0-25) + B(0-20) + C(0-12) + D(0-10) + E(0-8) = 75`

要达到 **70**，必须同时满足：

- **D ≥ 8** → `6h ≥ +20%` 且 `1h ≥ 0`（1h ≤ -20% 直接扣到 D2）
- **C ≥ 10** → 大致要 `MC ≥ $5M` + `LP ≥ $500K` + `vol ≥ $1M`
- 且 A ≥ 20（SM ≥ 8 或 KOL 强）、B ≥ 17（rug<0.1 / bundler<0.15 / top10<0.2 基本全绿）、E ≥ 5（真叙事）

**推论（2026-10-17 23:00 实测）**：市场一旦呈现「**大盘标的集体回调 + 动量盘全是微盘**」的分裂结构，70 分在数学上不可达——

- BSC 数据最干净的 `sauce`（SM175/KOL52/t10 12.7%/bundler 1.3%/rug 0）A25 B20 C8.5 **D4**（1h -16%）= 57.5，E 拉满也只有 65.5
- BSC 动量最强的 `yoki酱`（6h +663%）MC 仅 $193K → C5 → 57
- SOL 6h 榜首 `索拉纳` +17954% 是**开盘首日假象**，且 rug 0.98 → B8，48 分
- SOL `STONK` bundler 50.3% → B5；`FTR` bundler 45.5% + 6h -27.7% → D0

→ 遇到这种全场 55-62 的局面，**不要怀疑评分器坏了、也不要把门槛悄悄降到 60**。正确动作：写「本日无准推级」+ 一句话说明是「大盘回调（D 崩）+ 动量全是微盘（C 低）+ 首日爆量盘硬规则」三件事同时发生，然后照常出其余四段。这是 BSC 存量博弈市的典型形态，会反复出现。

```bash

  gmgn-cli market trending --chain bsc --interval 6h --limit 30 --raw > /tmp/alpha_bsc_6h_$(date +%s).json

# ③ TVL：直接跑 skill 内置脚本，不要用 tvl_monitor.py

```

- **TVL**：`tvl_monitor.py` 三链一律打印 `+0.0%`（DeFiLlama 24h 缺口），必须用 `scripts/tvl-7d-change.py` 才算得出真 7d 变化（本次 SOL -4.4% / BSC -1.9%）
- **批量 token info**：一条 bash 脚本 + `declare -A ADDR=([label]="chain|address")` + `JOB=<epoch>` 前缀 + 循环内 retry-once + `sleep 0.4`，代理**在脚本里 export**（不要靠调用方环境）。20 条 ~15s，零失败
- **E（叙事分）**：先用 `E_MAP={}` 占位跑一遍分，再对真正的头部候选抓 token info 按 `link.website` / `link.twitter_username` / `link.description` 反推叙事，手填 E 复算。叙事信息**只存在于 token info**，trending raw 只有 symbol

### 🆕 判据 A：同源模板双发（rat / dev-hold / bundle 三件套指纹）

两枚**不同名、不同赛道**的代币，若 `rat_trader_amount_rate`、`dev_team_hold_rate`、`bundler_rate` 三项**逐位近似**（本场 79.65/13.80/13.80 vs 79.25/13.77/13.77，差值 <0.5pp），且部署时间同窗（20 分钟内）、holder 数与 SM 数同量级 → **同一发盘脚本 / 同一 operator 双发**，不需要看价格动作即可定性。

- 与已有簇型区分：不是「共享推广链接」（website/tw 不同）、不是「秒级双链同窗」（同链）、不是「同名簇」（名字完全不同）
- 报告写法：两条都进新币段并各自标「不推」，然后在其中一条的 ⚠️ 行里点明「与 XXX 三项指标逐位相同 = 同源模板双发」，让读者看到两条是同一件事
- 识别价值：`rat_trader ≈ 79%` 本身就是老鼠仓占八成成交的派发特征，指纹重合只是把它从「单盘脏」升级为「有组织的连续收割」，对判断「这波首日爆量能不能接」是决定性证据

### 🆕 判据 B：零准推时，叙事段与建议段怎么填（格式 vs 禁令的冲突解法）

本 cron 的 Risk Rule 6 明禁「观察名单 / 60-69 观察级」，但输出格式又强制要求 `🧠 叙事验证` 段点名「最贴合标的」、`🎯 建议关注方向` 列 3 条。零准推场次这两段必然要提 <70 的名字，处理方式：

1. **叙事段开头加一行声明**：`> 本节只做叙事锚点与角度核对，不给分、不是推荐名单`——把它和「按分数排的观察名单」在性质上切开
2. **叙事段只提「角度正主 / 对位盘 / 复活线」**，每条必须给 symbol + 完整 CA + 一句贴合理由 + 一句结构缺陷（如「bundler 44%、已从高点 -70%」），**绝不写分数**
3. **建议段写「方向」不写「标的排序」**：三条各锁定一个可操作方向（新铸币 vs 老对位盘 / 等哪个数据条件出现 / 主动避开哪三类），每条用「(链)」标注
4. 全篇**任何位置都不出现 XX/75 的具体分数**（含最高分那一条）——只写「全场最高未达 70」的定性描述，这样既解释了 why，又不构成观察名单
5. 「BSC 成交 TOP5 全合成盘」的罗列：**只给金额不给符号**（$98M / $10.3M / $6.8M / $4.35M / $870K），既保留了信息量又不用为 5 个符号各配 CA

### ⚠️ 判据 C：`tvl-7d-change.py` 会单链失败（SSL EOF），要能单链兜底

本场 `scripts/tvl-7d-change.py` 输出 SOL ✅ / RH ✅ / **BSC FAIL `<urlopen error [SSL: UNEXPECTED_EOF_WHILE_READING]`>**——脚本不重试，该链直接缺数。兜底（不要因此整段写「BSC 数据缺失」）：

```bash
# 单链 curl（代理）落盘后按最近邻算 24h/7d；元素字段是 date(unix秒) + tvl(USD)
curl -s --max-time 25 "https://api.llama.fi/v2/historicalChainTvl/BSC" -o /tmp/bsc_tvl_hist.json
```

解析时 `closest(now)` / `closest(now-86400)` / `closest(now-7*86400)` 三个最近邻点，并**打印每个点的 gap 秒数**验证命中真实数据点（gap 应为 86400 / 604800，否则说明 DeFiLlama 有缺口、该变化率不可用）。注意 `tvl_monitor.py` 与 `tvl-7d-change.py` 的 24h 经常一个 +0.0% 一个真值，**以 gap 校验通过的 historical 计算为准**。
