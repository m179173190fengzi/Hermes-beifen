# 链上行为审计：没有日志也能归因（wallet_audit.py）

journal 是「往后记」，这一套是「往回看」——用链上活动记录反推用户**已经做过**的交易，
不需要他从今天开始记笔记。用户说「分析我的操作逻辑 / 我的交易随意性 / 我总是补仓」时用这个。

## 数据源

```bash
gmgn-cli portfolio activity --chain <bsc|sol|robinhood|base|eth> \
  --wallet <0x...|base58> --limit 100 [--cursor <next>] --raw
```

返回 `{"activities":[...], "next": <cursor>}`，**最新在最前**。

关键字段：

| 字段 | 含义 |
|---|---|
| `timestamp` | unix 秒 |
| `event_type` | `buy` / `sell`（也有 transferIn/Out、add/remove） |
| `token.address` / `token.symbol` | 标的 |
| `token_amount` | 数量 |
| `cost_usd` | 成交金额（USD） |
| `price_usd` | 成交单价 |

⚠️ **不要用 `portfolio stats` 的 winrate / buy / sell 字段**：实测 BSC 返回 `buy:0 sell:0`、
RH 返回 `winrate:1`（100%），与 activity 自算结果完全冲突。统计一律自己从 activity 算。

## 算法（成本均价法）

按时间升序回放每个 token：

```
buy  : qty += amt; cost += usd
sell : avg = cost/qty; pnl = usd - avg*min(amt, qty); qty -= amt; cost -= avg*amt
```

由它派生四组指标：

1. **逐笔结算** → 胜率、盈利合计、亏损合计、盈亏比
2. **持仓时长分桶** → 0-1min / 1-10min / 10min-1h / 1h-1d / >1d，每桶的合计与均值
3. **加仓分类**（在有持仓时再买）：`价 > 均价×1.02` = 追涨；`价 < 均价×0.98` = 补跌；其余 = 平摊
4. **回环**：同一 token 卖光后再买 = 「卖了又买回」

另外算**摩擦成本**：单笔亏损在 -$5 ~ 0 之间的合计，那基本就是手续费 + 滑点。

## 脚本

`~/.hermes/scripts/wallet_audit.py`

```bash
python3 wallet_audit.py --wallet 0x...                  # 全量审计（4 页/链，写 cache）
python3 wallet_audit.py --wallet 0x... --cached         # 复用上次抓取，秒出
python3 wallet_audit.py --wallet 0x... --today          # 只看 24h（静默：无交易则不输出）
```

`--today` 只取 1 页最新数据（分页深了反而可能拿到旧页），输出「今日 N 笔 + 违规标记」：
补跌加仓、小额交易（<$5）、卖出盈亏。wrapper：`~/.hermes/scripts/wallet_daily.sh`
→ 挂 `no_agent` cron（每日 21:00），**当天没交易就完全静默**。

## 判读：先验证用户的自我叙事，再开药

用户在 2026-11 的自述是「我总是喜欢补仓，还没吸取教训」。实测数据把这个说法推翻了一半：

| 指标 | 实测 |
|---|---|
| 卖出结算 | 45 笔，胜率 **36%**（16 赢 / 29 亏） |
| 盈亏比 | 赢的 5 笔均 +$21.49，输的 29 笔均 -$2.91 → **7.4 : 1** |
| 净已实现 | +$76（另一口径 +$97） |

**利润全部来自 >1 天的 5 笔（+$107.47），全部 1 小时内的交易合计 -$31.37。**

```
0-1 分钟     32 笔   -$11.21
1-10 分钟     5 笔   -$4.35
10 分钟-1 小时 3 笔   -$15.81
>1 天         5 笔   +$107.47   ← 全部利润
```

加仓 9 次里：补跌 6 / 平摊 2 / 追涨 1。**补仓恰恰是唯一赚大钱的动作**——
他在 -46%/-40%/-38% 连补三次，后来 3.5 倍卖出，+$97。

真正的三大伤害：

1. **卖出后买回**（7 次）。同一个币卖 0.0019 → 买回 0.00106 → 卖 0.00108 → 买回 0.00052，
   把 $160 的利润做成 $107。
2. **秒进秒出**（32 笔 0-1 分钟），纯摩擦。
3. **金额随机**：中位 $9.78、最大 $49、最小 $2.42、标准差 $9.89 ≈ 均值 → 没有仓位管理。

## 结论模板（不要只念数字）

四段，顺序固定：

1. **利润来自哪里**：哪一类（时长桶 / 盘型）在赚钱，占比多少
2. **亏损来自哪里**：同上，指出最大那一桶
3. **自我认知 vs 数据**：用户的说法哪一半对、哪一半错（必须引具体几笔）
4. **可执行规则**：每条都挂一个数据依据，例如
   - 补仓只在 -30% / -50% 两档，每次 ≤ 首仓 50%（依据：6 次补跌里只有 SEASON 那次有效）
   - 卖出后 24h 禁止买回同一币（依据：回环 7 次，约损耗 $50）
   - 单笔下限 $15（依据：24 笔 <$5 的摩擦合计 -$43）
   - 单币总投入 ≤ $60（依据：单币最高投入 $180）

## 坑

- **用户会把代币合约地址当钱包发过来**。先判格式与用途（DexScreener 查得到 pair = 代币合约），
  收款地址要单独确认，转错就是永久损失。
- **GMGN activity 分页不稳**：多页拉取时偶尔只返回更旧的一段。日常巡检用 `--today`（单页）更可靠。
- **不覆盖 CEX 交易**：只有链上活动。用户若在交易所下单，这套看不到，结论里要说明数据边界。
