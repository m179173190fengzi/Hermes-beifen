# 6 均线趋势确认（多头侧）

> 一句话：**均线解决「往哪边」，价格位置解决「现在贵不贵」。两者都过才是买点。**

## 1. 为什么是 6 条：双均线 × 2 种算法

| 算法 | 性格 | 作用 |
|---|---|---|
| **SMA**（慢、平滑） | 不容易被骗，但滞后 | 判断「结构有没有坏」 |
| **EMA**（快、敏感） | 早反应，假信号多 | 判断「现在强不强」 |
| **120 周期** | 第三级 | 过滤中级反弹 |

**两组同时多头 = 慢的没坏 + 快的也强**，这才是真发散。
SMA 多头但 EMA 已死叉 → 假突破；EMA 多头但 SMA60<SMA120 → 价格先冲、成本没理顺 → **假发散**。

**双均线的价值在「过滤」不在「预测」**：它让你只在一个方向下注。
死穴是震荡市反复金叉死叉 —— 所以必须有「均线密集（价差<3%）不动手」这一条。

## 2. 「站上全部均线」三条件（缺一条都不是买点）

| # | 条件 | 判别方法 |
|---|---|---|
| 1 | 收盘价 > 全部 6 条均线 | 必要但不充分 |
| 2 | **多头排列**：SMA20>SMA60>SMA120 **且** EMA20>EMA60>EMA120 | 缺 = 假发散 |
| 3 | **大周期同步**：1H 看多要先确认 4H 也站上 | 4H 还压在 SMA60 下方 = 反弹不是反转 |

**追高判据**：距 SMA20 **> +10%** 不进 —— 那是「已经涨过头」，不是「刚站上」。

**实测反例（USELESS 2026-10-20）**：
```
1H 价 0.1629 > 6 条均线        ✅ 条件1
SMA60 0.1438 < SMA120 0.1540   ❌ 条件2（非多头）
距 SMA20 +12.7%                ❌ 追高
4H SMA60 0.1663 > 价 0.1628    ❌ 条件3
→ 方向对、位置差，不能追
```

## 3. 告警：只报状态翻转，零 token

`scripts/ma-watch.py` —— 查任意 OKX instId 的 1H/4H，站上/跌回全部 6 条均线时**只输出一次**，
状态存 `~/.hermes/cron/state/ma_watch.json`。挂 `no_agent` cron 即零成本。

```bash
python3 ma-watch.py --inst USELESS-USDT-SWAP --bars 1H,4H   # 有翻转才打印
python3 ma-watch.py --inst BTC-USDT-SWAP --force            # 打印当前状态（不写告警）
```

输出含价、6 条均线值、排列（多头/非多头）、发散度、距 SMA20 百分比 ——
拿到就能判「真发散 vs 假发散」，不用再回头算。

**OKX 公共行情不需要 key**：`https://www.okx.com/api/v5/market/candles?instId=<inst>&bar=<1H|4H>&limit=200`
（代理环境下走 `HTTPS_PROXY`）。

**周期分层（2026-10 用户明确修正过，不要一刀切）**：
- **趋势 / 仓位决策 → 1H/4H**：这是原版 V4 的用法，条件 2、3（多头排列 + 大周期同步）必须过。
- **震荡市短线 → 1m/5m（用户明确要求）**：用户原话「现在是震荡市，只做1分钟，5分钟级别」。
  1m 回踩确实每天几十次，但用户要的正是这种高频小仓；**代价是假信号率大幅上升**，
  所以 1m/5m 上必须叠加下面的「密集 / 压缩 / BTC 锚定」三重过滤，否则等于盲赌。
- 不要再用「1m 是噪音所以不能做」去否定用户——他要的是用过滤条件把噪音压住，不是回避短周期。

## 4. 常见误读

| 误读 | 实际 |
|---|---|
| 「站上全部均线了，买」 | 还要看排列 + 大周期 + 距 MA20 |
| 「均线多头 = 可以追」 | 多头排列 + 价距 MA20 >10% = 追高区 |
| 「1 分钟回踩 MA20 是买点」 | 单看 1m 是噪音；用户做 1m/5m 时必须叠加密集 + BTC 锚定（见 §6）|
| 「等死叉再走」 | 滞后 10-20%，要有硬止损（EMA20 下方 3%）|
| 「站上 120 周期 = 反转」 | 单周期站上不算，必须 4H 同步 |

## 5. 与仓位规则的接口

- 信号成立后建仓 → 止损放 **EMA20 下方 3%**（不是斜着看 K 线）
- 加仓只在**盈利后**（利弗莫尔式：涨 10% 加），跌了加仓是另一套（333，仅用于有基本面的现货）
- **微盘 meme 不适用本 skill**：meme 用「翻倍出本 + 不补仓」，均线在微盘上会被对倒画出来
- 完整的三套仓位公式（333 建仓 / 721 持仓 / 251 止盈，含「2x 卖 20% 并不回本」的算术修正，
  以及与利弗莫尔阶梯的冲突与切换条件）见 `references/position-sizing-333-721-251.md`

## 6. 用户自用配置：1m/5m 震荡市短线 + BTC 锚定（2026-10 定稿）

用户原话：「**均线密集就是入场点，K线跌破就是出场点**」「**K线站上所有均线你就提醒我**」
「**K线第一次回踩20均线不破也是一次入场点位**」「**要锚定BTC，做useless，一般的BTC率先发动行情**」。

### 6.1 四条信号（全部状态翻转才报，不重复刷）

| 信号 | 判定 | 动作 |
|---|---|---|
| 🚨 **极限压缩** | 6 均线价差 **<1%** | 弹簧压到极限，准备；**BTC 上出现最有价值** |
| 🎯 **均线密集** | 价差 **<3%** | 蓄力区（用户定义的「入场区」）|
| 🟠 **BTC 发动** | BTC 收盘 > 全部 6 条均线 | 发令枪，先看 BTC 再看标的 |
| ✅ **共振入场** | 标的站上全部 6 条 **且** BTC 同周期也在上面 | 顺势做多 |
| ⚠️ **逆势信号** | 标的站上但 BTC 未确认 | **减半仓或不做** |
| ❌ **出场** | 收盘 < **EMA20** | 走，不等死叉 |

### 6.2 「第一次回踩 MA20 不破」的精确判定（容易做错）

三条同时成立，且必须是「多头排列」前提下：

```
① 多头排列   SMA20 > SMA60 > SMA120
② 低点触及   最低价 <= SMA20 × 1.002
③ 收盘不破   收盘 > SMA20 且 距 SMA20 < 1.5%
```

**「不破」只看收盘**，盘中插针不算破。**止损放 SMA20 下方 3%。**
注意：**跌破 SMA20 之后再站回去，性质是反抽不是回踩** —— 脚本用「多头排列 + 收盘站上」过滤，
但回答用户时要自己确认是不是「第一次」。

### 6.3 BTC 锚定的方向顺序（不要反）

```
① BTC 1m/5m 站上全部均线  → 发令枪
② 标的同周期跟涨          → 共振，可进
③ 标的先动而 BTC 没动     → 逆势，减半仓或不做
```

用户原话「一般的 BTC 率先发动行情」——**BTC 的密集/压缩是先行指标**，
标的自己走出形态但 BTC 还在均线下方时，那个形态大概率是假的。

### 6.4 落地脚本（现役）

`~/.hermes/scripts/ma_watch.py` —— 已实现上述全部信号 + BTC/标的双标的 + 状态去重：

```bash
python3 ~/.hermes/scripts/ma_watch.py --force          # 看当前 1m/5m 状态
python3 ~/.hermes/scripts/ma_watch.py                  # 只在翻转时输出（cron 用）
python3 ~/.hermes/scripts/ma_watch.py --bars 1H,4H     # 换周期
```

挂 `no_agent` cron（`* * * * *`，每分钟）＝ **零 token 常驻**；
状态文件 `~/.hermes/cron/state/ma_watch.json`，键为 `<inst>:<bar>`。

### 6.5 判读时必须先说的一句

**信号 ≠ 买点。** 站上全部均线只解决方向；还要报「距 SMA20 多少 %」——
>+10% 就是追高区，此时即使五条信号全亮也要说「方向对、位置差」。

**实测反例（USELESS 2026-10-20 23:04，1H）**：价 0.1629 已站上全部 6 条，
但 SMA60 0.1438 < SMA120 0.1540（非多头）+ 距 SMA20 **+12.7%** + 4H 仍在 SMA60 下方
→ 结论必须是「不能追」，而不是「信号成立」。

## 7. 多周期冲突与实现坑（实测踩过）

### 7.1 「大级别回踩、小级别先破」

```
5m：多头排列 + 价格贴着 EMA20（+0.19%）  → 结构内的回踩
1m：收盘已跌破 EMA20（-2.13%）           → 短线先转弱
```

这不是矛盾，是**同一个回踩在两个级别上进度不同**。两种处理，都要说清楚：

| 打法 | 做法 | 代价 |
|---|---|---|
| 稳 | 等 1m 重新站上 EMA20 再进 | 价格会高一点 |
| 快 | 5m 多头前提下，1m 一破就等、不追 | 可能错过一小段 |

**绝不能说成「1m 破了所以全出」** —— 出场信号看的是标的所在级别的 EMA20，不是随便哪个级别。

### 7.2 OKX K 线数据顺序（写脚本必踩）

`/api/v5/market/candles` 返回 **最新在 `data[0]`**。算均线前必须 `reversed()`，
取「本轮最低价」用 `rows[0][3]`（最新那根的 low），不要用 `rows[-1]` —— 那是 200 根前的老数据。

### 7.3 部署告警脚本：先播种，再上 cron

新脚本第一次跑时状态文件是空的，`above=False → True` 的翻转判定会把**当前已经成立的状态**
当成新信号立刻推一条（用户会收到一条"过期"告警）。

上线顺序：先 `--force` 跑一次（写入基线），再挂 cron。之后只有真正翻转才推。

### 7.4 `--force` 的标题必须按真实状态打

早期版本 `--force` 无论实际如何都印「K线站上全部均线」，导致「4H 还在均线下方」被写成"站上"。
`--force` 只用于让人看当前状态，**标题必须由 `above` / `below20` 实算得出**，
否则排查时会误判（用户会拿这张图当依据）。

### 7.5 暴拉过的标的：SMA 被历史低价污染，密集度直接失真

**实测（AXIS-USDT-SWAP 2026-10-22）**：6 小时 +209%，5 天内约 55 倍。

```
1H  SMA20  0.0279      ← 比现价 0.277 低 90%
1H  SMA120 0.00466     ← 低 98%
1H  EMA20  0.28134     ← 正常，贴着价格
算出来的「密集度」 100%  ← 纯噪声
```

**判据**：若 `SMA120 / 现价 < 0.3`（或任一 SMA 偏离现价 >60%），说明样本里混入了暴涨前的低价，
**SMA 系全部作废，密集度/压缩判定不可用**。

处理方法：
- 只看 **EMA20/60/120**（指数加权，老数据权重快速衰减）+ 价格结构（前高/前低/回踩位）
- 密集度不要报，或明确说「该标的涨幅过大，密集度无意义」
- 未平仓/刚上永续的新币尤其常见——交易所上新后 K 线历史短，SMA 的 120 根里可能大部分是更早期的低价

**反例警戒**：给用户报「密集度 98.9%」看着像极限压缩，实际是 SMA 被 0.005 的历史价拖死的假数字。
报之前先看 `SMA120` 与现价的倍数关系。
