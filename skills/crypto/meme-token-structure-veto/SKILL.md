# 结构否决层（meme 币）

> 一句话：**叙事决定「要不要看」，结构决定「能不能碰」。结构不过，叙事再好也只是别人的出货对象。**

## 0. 先判盘型（决定时机与仓位，比结构更早）

判别只要一句话：

> **这个 ticker，别人能不能想出第二个名字？**

| | 事件型 | 叙事型 |
|---|---|---|
| 例子 | PIERRE（人名）、爆款视频里的角色 | AI agent、政治、某个赛道词 |
| ticker 唯一性 | **唯一**（想不出第二个） | **发散**（几十个词都能当） |
| 动作 | **当天冲**（第一个盘就是答案） | **等 1-2 天看谁跑出来** |
| 仓位 | 小仓（承受 ~90% 归零率） | 大仓（付 3-10x 确认溢价，换 50-60% 存活率） |

SOL 尤其致命：pump.fun 发币成本≈0 → 同叙事分钟级复制。
**PIERRE 实测**：主盘 00:38 创建，04:36 已出第 8 个仿盘 → 手快没用，关键是 3 秒否掉 7 个错的。

**仓位必须跟着确定性走。** 反过来做（事件型重仓、叙事型小仓乱冲）是最贵的错误。

### 0.1 第三种：机制型（铸造 / 打新 / 身份门槛）

盘型不只按「事件 vs 叙事」分时机，还有一条正交的轴：**有没有真实资金动作在托底**。

| 类型 | 判别 | 定价依据 |
|---|---|---|
| 纯 meme | 只有 ticker + 图 | 情绪 |
| 蹭热点 meme | 好 ticker + 蹭当下事件（无产品） | 情绪 + 曝光 |
| **机制型** | **有 mint / 白名单 / 身份门槛 / 阶梯价 / 邀请返利** | **真实铸造现金流** |

判分口径：**真机制 > 蹭热点的好 ticker > 纯 ticker 盘**。

**实测 JAGENT（2026-10/11，BSC）**：必须持有 `.ai Agent ID` 的币安 Agentic Wallet 才能铸，
每个 ID 铸 10 份，总量 444 万份，阶梯价 1U 起涨到 8.07U（353 档），
每笔 80% 等 PancakeSwap 开池、**20% 直接进国库**，邀请 1 人 +1 份。
持币两天从 11,079 → 15,512（+40%）——**那不是「有人买」，是「有人在铸」**。

机制型盘必须额外算三笔账，任何一个算不清就别给入场建议：

1. **抽成**：每笔多少比例不进池（JAGENT 20%）→ 直接是项目方的无风险收入
2. **邀请返利**：多铸份额靠拉人 → 裂变结构，不是需求结构
3. **阶梯涨价**：越晚越贵（1U → 8.07U 是 8 倍成本差）→ 现在进场的成本劣势要明说

**最危险的状态**：铸还在继续（持币涨）而**二级缩量横盘**（1h 量掉 80%）——
说明没人愿意在二级接手，开池后价格容易直接崩给早期铸币者。

**动作分流**：
- 用户**有**身份/白名单 → 走铸造（结构性便宜），别在二级买
- 用户**没有** → 只能二级，面对 8 倍成本差的铸币者 + 围猎盘 → 不划算，直接说清楚

## 1. 三个核心比例

| 字段 | 含义 | 红线 |
|---|---|---|
| `stat.top_entrapment_trader_percentage` | **围猎盘**：行为聚类出的协同地址群占比 | **>30% 不碰；>50% 一票否决** |
| `stat.top_bundler_trader_percentage` | bundle：同区块/同批打包买入 | >25% 视为开局被狙击 |
| `stat.top_10_holder_rate` | Top10 集中度 | >40% 抛压集中；>50% 放弃 |
| `stat.bot_degen_rate` | **机器人占比** | >20% 成交是机器人刷的；>40% 基本没有真买盘 |

**围猎 ≠ bundle**：bundle 是「起跑线抢位」（TGE 瞬间打包买入），围猎是「整场做局」
（跨时间、多地址、同源资金养鱼）。后者更危险，因为走势更像自然行情。

实测对照：
```
PIERRE（30x 存活） 围猎 9.1%  bundle 18.1%  Top10 20.4%
SUPERCORE          围猎 11.7%
SEASON（典型围猎） 围猎 51.5% bundle 0      Top10 49.4%
```

### 1.1 Top10 干净 ≠ 安全：分散在小号里正是围猎手法

2026-10/11 实测四个盘（同一周、同一用户发的 CA）：

| 盘 | Top10 | bundle | 机器人 | 围猎 | 读法 |
|---|---|---|---|---|---|
| **JAGENT** | **6.0%** | 11.2% | **7.1%** | 40.4% | 三项最干净，但围猎超标 → 🟡 |
| Agentic Inu (.ai) | 17.2% | 21.1% | — | 42.6% | 叙事满分、结构红灯 |
| GANG | **14.3%** | **33.2%** | **51.7%** | 44.7% | Top10 看着干净，实际一半是机器人在对倒 |
| Kimchi (GTA式梗) | **78.2%** | 14.0% | 12.1% | **79.7%** | 极端控盘 |

**GANG 是最重要的反例**：Top10 只有 14.3%，按老标准会判「筹码分散 = 安全」，
但 bundle 33% + 机器人 51.7% + 围猎 44.7% → **筹码是分散到几十个小号里，不是分散到真实用户手里**。

**规则：Top10 只作为辅助项，任何一个盘必须四项一起看（围猎 / bundle / 机器人 / Top10）。**
四项里有两项红就否决，不要拿「Top10 低」去对冲「围猎高」。

### 1.2 单一大地址 > 50%：先查它是不是池子/创建者，不要直接当鲸鱼

实测 Kimchi：TOP1 持 **75%**，`买入 $0 / 卖出 $0`，而且该地址就是官网链接指向的
`pump.fun/profile/<addr>` —— 是创建者档案/池子型地址，不是随时砸盘的鲸鱼。

**三步判定**：

```bash
gmgn-cli token holders --chain sol --address <CA> --limit 8 --raw
# 看 TOP1：buy_volume_cur / sell_volume_cur
```

| 特征 | 结论 |
|---|---|
| 买卖量都是 0 / null | 静态持有 → 池子、锁仓、或创建者档案 |
| 有真实买卖量 | 活的筹码 → 按 >50% 直接否决 |
| 地址 = 官网/推特链接里的 profile 地址 | 创建者自留，重点看它历史上有没有清仓记录 |

**但结论不变**：无论那 75% 是池子还是创建者，**流通盘都只有 25%**，
再叠加围猎 79.7% → 仍然是不碰。区分性质是为了说清「为什么」，不是为了给它翻案。

### 1.3 围猎低 ≠ 安全：低围猎 + 高 bundle 是另一种控盘

同期两个盘的对照（都是 24h 10 倍以上、都在跌）：

| 盘 | 围猎 | bundle | 机器人 | 机器 | 真相 |
|---|---|---|---|---|---|
| GREEN MORNING | 21.6% | **0.6%** | 13.2% | 24h +1975% / 1h -21.6% | **真拉真砸**：筹码真散、卖压真的来自人 |
| PUSSYCOIN | **17.3%** | **64.4%** | **68.9%** | 6h +1135% / 1h -23.8% | **机器人对倒假拉**：开盘 64% 被脚本包走 |

**读法**：围猎和 bundle 是两种不同的控盘时间点 ——

- **bundle 高 = 先天控盘**（开盘瞬间打包买入）。控盘方开局就握着货，**根本不需要围猎**，
  所以「围猎只有 17%」在这里什么也不证明。
- **围猎高 = 后天做局**（多地址跨时间养鱼），走势反而更像自然行情，也更难识别。
- **bundle 高 + 机器人高 = 对倒假拉**：成交量放大但持币增长慢、买卖笔数接近而价格单边下跌，
  热度是脚本自己跟自己成交做出来的。

**硬规则：围猎、bundle、机器人三项里任一项超线就否决，不能拿「围猎低」去对冲「bundle 高」。**
真正的干净样板是三项都低（上面 GREEN MORNING 的 21.6 / 0.6 / 13.2 是少见的全绿结构），
这种盘可以只等位置；三项里有一项灾难级（bundle >50% 或 bots >60%）的盘，
**跌多少都不能碰** —— 你无法判断它什么时候二次拉盘割人。

### 1.4 平台币（launchpad 本币）：定价锚在平台数据，不在 K 线

有的盘不是「某个梗」，而是**一个发币平台自己的代币**（官网写着 launchpad / 一键发币 / 手续费分成 /
卡片消费，路线图指向更多链）。这类盘 K 线的意义要换一套读法：

| 判断对象 | 该看什么 |
|---|---|
| 纯 meme | 情绪、位置、结构 |
| **平台币** | **平台日发射数、手续费收入、路线图兼现**；K 线只是情绪的投影 |

- 结论里「等什么」必须写成**产品指标**（日发射多少、Fees 多少、多链是否上线），不是「MC 回到多少」。
- 平台币的 bundle 高不等于必死（真实需求能把早期筹码消化掉），但**只有平台数据能证明这一点**；
  拿不到平台数据就仍按结构否决处理，**别用「它是个产品」给它翻案**。
- `dev.creator_token_status`：`creator_close` = 已清仓；`creator_hold` = 还在持。
  后者不是利好也不是利空，是「它还在这局里」——但它的持仓要从流通盘里扣掉再算抛压。

### 1.5 极端换手与笔数不对称：机器人对倒的量化指纹

```
换手倍数 = 24h 成交量 ÷ MC
```

| 换手 | 含义 |
|---|---|
| 1-4x | 正常活跃 |
| 4-10x | 很热，盯位置 |
| **>15x** | 极可能是机器人对倒；配合 `bot_degen_rate > 40%` 直接按假拉处理 |

实测 MAX（Solana launchpad 币）：MC $2.5M、24h 量 $54.5M = **21.8x 换手**、24h **43.6 万笔**、
bots 46.35% → 量是真的，热度是脚本造的。

**笔数方向的读法（比净额有用）**：价格 1h 跌 20%+，但**买笔数 > 卖笔数** →
卖的是少数大额、买的是大量小额 = **大户在出货，散户在接**，这是最后一棒。

```
1h 买 2,398 / 卖 1,919  +  1h -25.2%   → 大户单笔砸、散户小额接（表面买盘还占优，最易误判）
1h 买 288   / 卖 296    +  涨势停滞     → 卖方反超，第一波结束
```

**配套：多个大地址 `buy_volume_cur` / `sell_volume_cur` 全为 0 且合计 >10% → 锁定筹码**（团队/池子），
从抛压里剔除，但**要重算流通盘**（MAX 的 TOP1+TOP2 = 11% 零动作，真实可卖筹码比 Top10 显示的小）。

## 2. 两种典型矛盾组合（别被表象骗）

**官方皮 + 围猎内核**（有官网/docs/推特/白皮书）：
dev `creator_close`（已清仓）+ LP 未锁 + 池子碎 + 围猎 >50% → **一票否决**。
理由：游戏/应用盘要几个月养用户，围猎盘只做几小时收割，两者不可能同时成立。

**叙事强 + 结构烂**（爆款事件盘）：
dev 已清仓、bundle 18%、Top10 20%，照样能 30 倍。
→ **事件盘的定价权在社区情绪，不在 dev**，硬结构标准可放宽一档；
但围猎比例仍是硬线（PIERRE 只有 9.1%，这是它能活的隐含条件）。

## 3. 流动性碎裂

`池数 > 5` 且 `主池 LP / MC < 0.05` → 就算看对也跑不掉。
判据：**LP 集中到单池且 > $150K** 才算有进出深度。
测法：`jq '[.pairs[]|{lp:.liquidity.usd}] | {n:length, sum:(map(.lp)|add), max:(map(.lp)|max)}'`

### 3.2 进出成本用「报价的滑点字段」量，不要靠 LP 大小猜

LP 只能定性（薄/厚），真要做决定得拿一笔真实报价，读它的 `slippage`：

```
baw market-order quote --binanceChainId 4663 \
  --fromTokenQty 0.05 --fromToken 0xeeee...eeee --toToken <CA>
→ {"toCoinAmount":"204084.24","slippage":0.1588}
```

实测 SEASON：0.05 ETH（≈$195）→ 204,084 枚（按现价只值 $163）→ **滑点 15.88%，一进就亏 16%**，
出去再滑一次 → 进出合计 ~30%。这就是「$84K 主池碎在 18 个池」的定量代价。

**规矩**：给「能不能买」的结论前，先报一行「滑点 X% + 进出合计约 2X%」。
滑点 >5% 就不该做；想等它变好，条件是**主池 LP > $300K**（滑点通常回到 3% 以内）。


## 4. 时间信号：买卖笔数翻转

```
24h 买 4,990 / 卖 3,367  → 买方主导
1h  买 288  / 卖 296     → 卖方反超 = 第一波结束
```
买卖比由多转空的那一刻就是最后一棒交接，**比看 K 线早**。

## 3.1 LP 收缩是最早的撤离信号（比价格早）

价格还在涨、LP 在掉 = **边拉边撤**。实测 SEASON：`主池 LP $84,240 → $66,906（-21%）`，
同期 1h 还是 +26.6%。含义：
- 池子变薄后，同一笔卖单的滑点成倍放大 → 你就算看对也出不来
- 做局方可以在你之前先卖，因为池子已经装不下那么多了

**动作**：把 LP 绝对值当独立告警指标（LP 再掉 15-20% 就报），不要只盯价格。
买之前先看 LP 趋势，别只看当下的 LP 数字。

## 4.1 转钱前先验地址性质（用户会把 CA 当钱包）

用户给过一个地址让「把 104U 转进去」，那个地址其实是 **SEASON 的代币合约**（DexScreener
里是某交易对的 baseToken、GMGN 有 symbol/decimals）→ 转进合约 = 资产直接消失。

**3 秒判别**：DexScreener `pairs[].baseToken.address` 或 GMGN `token info` 能查到 =
**代币合约，不能收款**；能查到的地址里，用户自己的钱包地址只能来自 `baw wallet address`
/GMGN portfolio 查询，不能靠用户贴的字符串。

**规矩**：任何转账前先确认「这是 EOA 还是合约」，并向用户复述一次目标地址 + 链，再执行。

### 4.2 老盘复活：创建时间 × 涨幅必须交叉看

`pairCreatedAt` 是几周前、却在 24h 内涨 1000%+ —— 这**不是新叙事启动，是操盘手把冷盘拉起来出货**。

```
创建 5 周前 | 24h +1975% | 6h +81% | 1h -21.6%   → 老盘复活、拉高派发
创建 26h   | 24h +334%  | 6h +157% | 1h +88%    → 真新盘（位置差，但性质不同）
```

**判据：创建 > 7 天 且 24h 涨幅 > 500% → 默认按「老盘复活/出货」处理**，不要当新叙事给它开确认溢价。
配套确认两件事：① 1h 买卖笔数是否已经翻转；② TOP1 是否已净卖出
（`buy_volume_cur` vs `sell_volume_cur` 相减）。实测那次 1h -21.6% 的同时 TOP1 买 $28,014 / 卖 $38,845，
净出 $10.8K —— 主力和价格是同一个信号。

### 4.3 KOL/车头喊单证伪：看量能有没有被抬起来

喊单本身不是信号，**喊单之后的量能变化才是**。只看一个比值：

```
喊单后 1h 成交量 ÷ 24h 成交量
> 5%   → 有增量资金进场，喊单有效
1-5%   → 只是消耗存量关注，等回落
< 1%   → 喊单无效，当下就在派发段
```

实测 mihao（Solana）：24h 量 $18.6M → 6h $2.46M → 1h $149K = **0.8%**，
同期 1h 买 1,104 / 卖 1,169（净卖出）、bundle 50.6% / 围猎 36% → 典型「喊单余温里派发」。

配套三条一起核对，缺一条都别下结论：

1. **喊的目标价是不是早就走过了** —— 喊「速通千万」而 MC 已 $16M，那喊的是更高位接盘。
2. **同名仿盘有没有出现** —— `mihao wif hat`（$86K）这种派生盘出现 = 叙事已被消费过。
3. **币龄** —— 18 天的老盘 + 突然喊单 = 复活盘出货，不是新叙事启动（见 4.2）。

**推论：单盘速通 ≠ 行情发动。** 存量市场里一个盘速通必然对应另外几个盘归零；
判断「行情是否发动」用 `narrative-diffusion-monitoring` 的五条件清单，不要用单个 KOL 的喊单。

## 5. GMGN 原始字段坑（写脚本必踩）
- `is_honeypot` 是**字符串** `"no"/"yes"`，不是布尔 → 用 `0/False` 判断会把所有盘判成蜜罐
  （实测 BSC flap 币全中招）。
- `burn_status` 同样是字符串（`"yes"` = LP 已烧），不是 `"burned"`。
- `liquidity` / `market_cap` 是字符串数字，先 `float()`。
- `token holders` 对新链/非标准合约常返回 `{"list":[]}` → 改走 GoPlus
  `api.gopluslabs.io/api/v1/token_security/<chainId>?contract_addresses=<CA>`（新链也可能全 null，
  那就只能靠 DexScreener 的池子分布判断）。
- `gmgn-cli token info --chain robinhood` **现在可用**（holders/top10/entrap/dev/launchpad 都有），
  RH 链不再只能看 trending。
- **`price` 是个对象，不是数字。** `token info` 返回里 `price` = `{"price": "0.00016…", "price_1h": …}`，
  真价在 **`.price.price`**；`ath_price` / `total_supply` 才是顶层标量。
  直接 `float(info["price"])` 不报错但得 0 → 整张表的 MC 全变成 `$0.00M`（ATH 还能算、现价全 0 就是这个原因）。
- **`market kline` 的时间戳是毫秒**，而 `creation_timestamp` 是秒。
  两者相减算「见顶用时」会把 4 小时算成 4.97 亿小时 —— 统一 `if t > 1e11: t //= 1000` 再算。
- 倒回历史峰值优先用 `ath_price`（现成字段）；要算**见顶时间**才需要拉 kline 自己扫 `high` 最大值，
  别默认每只币都拉 K 线（一次一币，10 个币就一分多钟）。

## 5.1 DexScreener 的 marketCap 不可直接信（实测踩过）

`pairs[].marketCap` 在不同池子上会给出**互相矛盾**的值。实测 SEASON：
```
某池 marketCap = $766,586   ← 取 max 就会报错
真实 = priceUsd 0.0005306 × 供应 1e9 = $530,600   ← 用户说的 530K 才对
```

**规则：MC 一律用 `priceUsd × totalSupply` 自算，DexScreener 的 marketCap 只当参考。**
多池取 max 是错的做法 —— 正确做法是先按 LP 找主池，再自算。
被用户纠正过一次（"现在还是530K不是700多K"），以后报 MC 必须交叉验证。

## 5.2 GMGN portfolio 的返回结构（跟 token info 不一样）

```
gmgn-cli token info ...      → {"symbol": ..., "stat": {...}}        # 顶层
gmgn-cli portfolio holdings  → {"list": [{token, balance, usd_value,
                                           accu_cost, history_bought_cost,
                                           history_total_buys, history_sold_amount}]}
```
- 是 **`{"list": ...}` 裸结构，没有 `.data` 包一层**；参数是 `--wallet` 不是 `--address`。
- 校验用户自报成本用 `accu_cost / history_bought_cost` + `history_bought_amount`，
  解出成交均价 → 反推当时 MC，比"用户说 560K"更硬。
- `history_sold_amount = 0` 表示还没卖过（判断"是否已出本"直接看这个）。

## 6. 新链专属（RH / Base）

- 新链的「链级成交量」很可能来自**代币化股票**（RH：SPY/NVDA/SPCX 日成交各千万级），不是打狗。
  判 meme 热度要看该链 launchpad（RH：`pons`/`pons_v2`/`orbofi`）的盘。
- 新链围猎比例可能混入**项目方做市/初始分发**：长期持有 + 持续加 LP = 做市；拉高即清仓 = 围猎。
- 为一个 $800K 的盘去开通新链（桥、gas、钱包交互都要重学）风险收益比通常不划算。
- 「链上第一个 XX」的溢价通常落在**台子本币**（链的 beta），不是第一个应用币（链的 alpha）。
- **RH 段经常「0 个过线」不代表扫描坏了**：实测 `market trenches --chain robinhood` 的新盘常态是
  `MC $4,600 / 持币 2 / LP≈0 / 量 null`（flap、bankr 台子分钟级铺量），天然过不了
  MC≥$1M + 持币≥200 + 量≥$50K 的硬门槛。RH 的候选只会在**已经跑起来的成熟盘**出现；
  另外 RH 链上 `trenches` 返回的是顶层键（`completed`/`new_creation`/…），不是 `.data` 包一层。
