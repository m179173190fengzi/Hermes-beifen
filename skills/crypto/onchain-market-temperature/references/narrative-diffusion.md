# 叙事层温度：扩散计数（零 LLM）

链上成交量回答「还有多少钱在转」，叙事扩散回答「还有没有新故事在长」。
两者背离时，后者领先：钱先枯，故事后死；故事先起，钱才回来。

现成脚本：`scripts/narrative_radar.py`（本 skill 目录内，拷到 `~/.hermes/scripts/` 用）。

```bash
export HTTPS_PROXY=http://127.0.0.1:7890
python3 narrative_radar.py --hours 24            # 日报口径
python3 narrative_radar.py --hours 6 --min-events 3   # 盘中只抓强信号
```

## 核心口径：数「独立事件」，不是数「条目」

一篇通稿被 8 家媒体转载 = **1 个事件、8 个渠道**，不是 8 个独立信号。
第一次跑出来的表如果「稳定币 8 个源」里 6 条是币安活动文案，说明口径错了，不是市场热。

| 独立事件数 | 含义 | 动作 |
|---|---|---|
| 1 | 单一媒体/KOL 在说 | 忽略 |
| 2-3 | 开始扩散 | 记下来，盯 24h |
| 4-6 | 市场已确认 | 可按叙事布局 |
| 7+ | 全市场共识 | **已是退出窗口，不是入场** |

这条梯度正好量化了「事件型当天冲 / 叙事型等 1-2 天付确认溢价」里的「确认」。

## 交付形态：`--brief` 三行

用户要的是能直接读的一行结论，不是表。`--brief` 固定 3 行、进度全静默：

```
最强叙事  Meme 币 · 14 事件 / 12 域名
链        SOL×2 BSC×2 RH×1
读数     稳定币在收缩（链上子弹变少）；全市场共识 = 派发段，别追
```

- **第 2 行**：所有叙事命中的链计数，最多三个。没指向就写「无明确链条指向」。
- **第 3 行是叠加式规则**（最多两条，顺序即优先级）：
  1. `稳定币 ≥ 4 事件` → 流动性闸门（链上子弹变少）
  2. `Meme 币 ≥ 7 事件` 且不是最强那一条 → meme 已是共识区
  3. 扩散梯度：`≥7` 派发段别追 / `4-6` 已被确认可布局 / `2-3` 刚扩散等确认 / 无命中则「信号弱，观察」

### 双时间窗读法（别当成矛盾）

同一时刻跑 `--hours 24` 和 `--hours 6` 会得到相反读数，这是两个尺度，不是打架：

```
24h：meme 14 事件 + 稳定币 8 事件  → 别追（大方向：只减不加）
6h ：Solana 5 事件                  → 可布局（局部：短窗口有标的在动）
```

**规矩：大方向定仓位（24h），小窗口定标的（6h）。** 短窗口的「可布局」不是加仓许可——
拿局部机会盖全局风险，就是重仓接盘的典型路径。

## 四个必须做的过滤（少一个结果就不可用）

1. **标题命中才算，正文提及不算。** 加密站正文里什么都提，正文匹配会让每个叙事都命中。
2. **转载折叠（Jaccard ≥ 0.55）。** Google News 把同一篇稿铺到十几个域名，不折叠就虚高 5-10 倍。折叠后仍把「转载量」单列，它本身是热度信息。
3. **Google News 必须解析 `<source>` 拿原始媒体域名**，并把标题尾部的 ` - 媒体名` 剥掉。不剥，媒体名里的 “Crypto Briefing” 会让泛化叙事通过加密上下文检查。
4. **泛化叙事要过加密上下文闸门。** `AI Agent` / `监管` / `DeFi` / `Layer2` / `ETF` 这些词在主流新闻里到处都是——没有 crypto/token/chain/dex 等词同现就丢掉，否则「美联航禁止第三方 AI 代理订票」会被算成 crypto 叙事（实测 17 条事件全是噪音）。

另外两类要滤：
- **交易所活动/SEO 垃圾稿**（referral / earn up to / price today / price prediction / how to buy / “what happened in crypto today”）。它们用 USDC 等词把「稳定币」刷上去。
- **Telegram 公开频道**（`t.me/s/<channel>`）抓得到但没时间戳，一律按「现在」计，所以只当补充源，不做时间序列。

## 读数怎么写进日报

只写两件事：**最强叙事 + 它和链上温度是否同向**。

- 叙事多 + 链上量升 = 真行情，可按叙事布局
- 叙事多 + 链上量枯 = 只有话题没有子弹，等
- 叙事少 + 链上量枯 = 空仓期，去补录历史交易/校准过滤器
- 稳定币供应收缩（新闻里出现 “stablecoin supply drops … largest contraction”）是**流动性抽水**，比任何单个 CA 的体检都重要——它决定未来一周该不该开新仓

## 成本

纯字符串统计：0 次 LLM 调用、0 token。一次 24h 采集约 200-300 条、耗时 30-60 秒（走代理）。
对比 Horizon 这类 LLM 新闻雷达：每条要打分 + 摘要 + 联网富化，约 100 万 token/天（DeepSeek 约 ¥1-2/天）。
要「能读的日报」才付这个钱；只要「扩散计数」就用本脚本。
