**https://github.com/wsleepan/bitcoin-daily-onchain-report**

韩国开发者用 **Claude Code 定时任务**（云上跑）做的 BTC 每日链上日报系统。

**架构**：
- `ANALYSIS_PROMPT.md` → 完整的执行 Prompt（数据采集+评分+报告模板）
- `reports/YYYY-MM-DD.md` → 每日生成的报告文件
- `reports/SUMMARY.md` → 累积摘要表
- Telegram Bot 发送摘要 + 附件

**数据源**（全部免费）：
- CoinGecko → 价格/市值/交易量
- blockchain.com Charts → 算力/难度/活跃地址/交易数
- mempool.space → 费用/难度调整
- alternative.me → Fear & Greed Index
- CoinMetrics Community → MVRV

**评分体系**：规则打分表（-7 ~ +7），**F&G+2（逆向），MVRV+2，算力趋势+1，活跃地址+1，30日价格动量+1** → 总分判定买/卖/观望

**和你的对比**：它只搞 BTC 单链，你没有 Nansen 但有 GMGN + OKX OnchainOS 全套，数据面其实更宽

## 硬伤

**1. MCP 端点不对**
文章说加 `https://agent.robinhood.com/mcp/trading` — 这是 Robinhood **传统券商**的 Trading MCP，不是 Robinhood Chain 的链上数据接口。这个 MCP 给你的是股票/期权盘口，不是你想要的链上代币/聪明钱数据。我们实际用的是 **OKX OnchainOS + GMGN** 这套来扫 RH 链，不是连 Robinhood 官方 MCP。

**2. "Hermes Desktop" 不存在**
Hermes 没出过 Desktop 版（至少目前没有），它跑在终端/CLI/TG bot 里。文章里"打开 Hermes Desktop → 创建 workspace"这套流程是编的。

**3. 写得太泛**
Workflow 1 说"让 Hermes 监控一切" — 但没写**监控什么、怎么过滤、什么算重要**。我们实际跑的 6类过滤器+评分系统+跨链叙事映射 比这个具体10倍。

Workflow 2 说"Autonomous Trading Agent" — 但给的是 Robinhood 传统证券的 MCP，不是 RH Chain 的链上交易。如果要真做 RH Chain 上的自动交易，得走 OKX Agentic Wallet + GMGN swap 或者 DEX，文章没提这个。

Workflow 3 的 Virtuals Protocol 是真东西，RH Chain 确实集成了 Virtuals，可以发币化 Agent。但这个跟 Hermes 的关系写得很虚——"Link Hermes to the agent (via ID/contract tools)"，没写具体怎么做。
